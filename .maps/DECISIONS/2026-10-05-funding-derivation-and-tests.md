DECISION: Use Node's built-in test runner (`node:test`) with `tsx` for TypeScript data-layer tests; store funding amounts as integer minor units; keep amount_raised derived from verified successful payment_records rather than a writable project column.
DATE: 2026-10-05
REASON: TASK-002 requires schema/migration validation and data-layer tests with draft/published/unapproved-suggestion fixtures. The built-in test runner needs no test framework dependency beyond `tsx` for TypeScript path-alias support. Integer minor units avoid floating-point money errors for UPI-style donations. Deriving amount raised from verified successful payments matches ARCHITECTURE_MAP section 8 (amount raised is an authoritative application total from verified records, not an owner-editable field).
ALTERNATIVES CONSIDERED: vitest/jest (heavier dependency for a small data layer); storing amount raised on the projects table (risks totals drifting from payment truth and weakens the verification boundary); floating-point currency columns (precision risk).
TRADEOFF: `node:test` has fewer ecosystem conveniences than vitest. A stored generated column would make totals faster to query but weaker in trustworthiness; derivation is recomputed in SQL from payment_records.
AFFECTED COMPONENTS: Data-layer verification, Funding component (later tasks), Payment Integration (later tasks), Project Content persistence.
